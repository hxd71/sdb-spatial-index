# SDB Spatial Index

一个基于 C++ 的二维空间索引与可视化示例项目。项目围绕点、线、面几何数据，实现空间对象的包围盒管理、空间索引构建以及交互式查询，并使用 OpenGL/FreeGLUT 对查询结果和索引结构进行可视化。

## 功能概览

- **几何模型**
  - `Point`
  - `LineString`
  - `Polygon`
  - `Envelope`（轴对齐包围盒）
- **几何计算**
  - 包围盒包含、相交与合并
  - 点、线、面之间的欧式距离计算
  - 几何对象与查询矩形的相交判断
- **空间索引**
  - 四叉树（`QuadTree`）
  - R 树（`RTree`）
  - 区域查询（Range Query）
  - 最近邻候选查询（Nearest Neighbor）
  - 四叉树 k 近邻查询（k-NN）
  - 基于距离阈值的空间连接（Spatial Join）
- **可视化交互**
  - 加载纽约地区的自行车站点、出租车点、道路和多边形数据
  - 鼠标框选区域进行查询
  - 鼠标移动实时执行最近邻和 k 近邻查询
  - 显示或隐藏道路、空间索引边界及查询结果

> 当前程序首先通过空间索引筛选候选对象，再使用几何对象自身的精确相交或距离计算完成精炼。因此，索引查询结果适合作为候选集，而不是直接替代精确几何判断。

## 项目结构

```text
.
├── Geometry.h/.cpp       # 几何类型与几何运算
├── Tree.h                # Feature 和空间索引基类

├── RTree.h/.cpp          # R 树索引
├── QuadTreeTest.cpp      # 四叉树测试与分析
├── RTreeTest.cpp         # R 树测试与分析

├── 3rd/freeglut/         # FreeGLUT
└── 3rd/shapelib/         # Shapefile 读取支持
```

## 构建环境

- CMake 3.16 或更高版本
- 支持 C++17 的编译器
- OpenGL 和 GLU
- Linux/macOS 通常还需要系统提供 X11 相关开发库；Windows 可使用 Visual Studio 的 OpenGL 环境

项目已在 `3rd/` 中包含 FreeGLUT 和 Shapelib 的源码，普通构建不需要额外下载这两个依赖。OpenGL 本身仍需由系统提供。

## 构建与运行

```bash
cmake -S . -B build
cmake --build build --config Release
```

构建完成后，可执行文件通常位于：

- Linux/macOS：`build/hw6_app`
- Visual Studio 多配置生成器：`build/Release/hw6_app.exe`

如果构建目录或生成器的输出路径不同，请以 CMake 实际生成结果为准。

## 选择索引实现

默认使用四叉树：

```cpp
// Common.h
//#define USE_RTREE
```

取消注释后将使用 R 树：

```cpp
#define USE_RTREE
```

该宏会影响 `hw6.cpp` 中点、道路和多边形索引树的具体类型。修改后请重新配置或重新构建项目。

## 数据格式

示例数据使用 Shapefile 格式。程序会从 `data/` 目录读取对应的 `.shp` 文件，并在可用时读取 `.dbf` 中的名称属性，例如：

```text
data/station.shp
data/station.dbf
data/highway.shp
data/polygon.shp
```

其中点、道路和多边形数据分别用于构建不同的空间索引。若数据文件缺失，程序会输出错误或警告信息。

## 测试与四叉树 / R 树对比

项目中的 `QuadTreeTest.cpp` 和 `RTreeTest.cpp` 提供了几何计算、空间索引构建、空间连接以及性能分析入口。测试通过程序启动后的数字键触发；由于 `hw6.cpp` 根据 `USE_RTREE` 选择具体索引类型，同一组按键会作用于当前选中的索引。

### 功能测试

两种索引实现共享大部分基础几何测试：

- **测试 1：** `Envelope` 的包含、相交和合并
- **测试 2：** 点到线的距离
- **测试 3：** 点到多边形的距离
- **测试 4：** 索引构建结果
- **测试 5：** 四叉树中包含距离阈值的 Spatial Join 测试
- **测试 6：** 多边形与包围盒的相交判断（R 树测试中包含）
- **测试 7：** R 树或四叉树的构建统计
- **测试 8：** 索引性能分析入口

### 构建结果对比

源码中的构建测试使用固定数据集和固定索引参数，预期结果如下。节点数量和树高用于验证索引结构是否正确构建，并不代表所有数据集上的绝对性能。

| 数据集 | 索引 | 参数 | 树高 | 内部节点数 | 叶节点数 |
| --- | --- | ---: | ---: | ---: | ---: |
| `data/polygon` | 四叉树 | capacity = 1 | 6 | 8 | 25 |
| `data/highway` | 四叉树 | capacity = 20 | 11 | 1,386 | 4,159 |
| `data/station` | R 树 | maxChildren = 8 | 4 | 18 | 86 |
| `data/highway` | R 树 | maxChildren = 8 | 6 | 484 | 2,305 |

从这些固定测试可以观察到：

- 四叉树按空间递归划分，每个内部节点最多产生四个子区域；线数据的几何范围较长，可能跨越多个子区域，因此会产生较多叶节点和较深的树。
- R 树按节点包围盒组织对象，节点扇出由 `maxChildren` 控制；在当前 `highway` 数据集和参数下，R 树的高度与节点数量低于四叉树。
- 两种结构的节点数量不能脱离构建参数和数据分布单独比较。四叉树使用空间容量参数，R 树使用最大子节点数，二者的参数含义并不完全相同。

### 性能分析

测试代码中的性能分析使用 `data/taxi` 数据，并计划遍历不同容量参数，对构建时间和 100,000 次最近邻候选查询进行统计。运行入口为测试 **8**：

```text
8  -> 运行当前索引的性能分析
```

当前仓库中的分析函数仍包含待完善的分析逻辑：四叉树分析中的构建、节点统计和精炼步骤标记为 `TODO`，R 树分析中的 `forConstCapAnalyseRTree` 也尚未输出完整的对比指标。因此，README 中不虚构具体的耗时、吞吐量或“谁一定更快”的结论；实际性能应在相同编译配置、相同数据、相同查询点和相同容量参数下分别运行并记录。

建议记录以下指标：

| 指标 | 说明 |
| --- | --- |
| Construction time | 从输入几何对象构建索引的耗时 |
| Tree height | 索引树高度 |
| Interior node number | 内部节点数量 |
| Leaf node number | 叶节点数量 |
| NNQuery time | 固定数量最近邻候选查询的总耗时 |
| Candidate count | 精确精炼前返回的候选对象数量 |

一个公平的对比流程是：先使用相同的 `data/taxi` 数据，再分别编译四叉树和 R 树版本；随后使用相同的容量/扇出参数范围和相同的随机查询点，重复运行测试并取多次结果的平均值。对于最终的最近邻结果，还需要统计精炼步骤后的正确性，不能只比较索引过滤阶段的耗时。

## 设计说明

查询流程大致分为两步：

1. **索引过滤**：四叉树或 R 树根据对象包围盒快速返回候选集。
2. **精确精炼**：调用 `Geometry::intersects` 或 `Geometry::distance` 对候选对象进行精确判断，并去除重复结果。

四叉树通过递归划分空间构建层次结构；R 树则以节点包围盒组织空间对象。两种索引都提供统一的 `Tree` 接口，因此可通过 `USE_RTREE` 在不修改上层交互代码的情况下切换实现。
